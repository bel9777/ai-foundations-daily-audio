Alex: Asking an AI to solve a multi-step task isn't just about getting a quick answer; it's about giving the system room to plan, act, and check its work. This is AI Foundations, day 43. Today we're tackling agents. Jordan, up until now, we've talked about models answering questions or using tools when we ask them to, but agents feel like a step beyond that.
Jordan: They really are. Think of a simple chatbot as asking a knowledgeable person one question at a time. An agent is more like giving a capable assistant a goal, like asking them to find three affordable flights, compare them, and tell you which is best. The assistant decides what to do next, not just what to say next.
Alex: So instead of just generating a response in one shot, an agent works toward an outcome over several steps.
Jordan: Exactly. And that starts with three core concepts: a goal, a plan, and actions. The goal is the outcome you want. The plan is the sequence of steps the system expects to follow. And an action is one concrete move, like searching a database, running a code tool, drafting text, or asking a clarifying question.
Alex: Does an agent always map out the whole plan up front before doing anything?
Jordan: Not always. Some agents write down a full plan first, while others improvise one step at a time. But in both cases, the model isn't just generating text. It is constantly deciding what action to take next to reach the goal.
Alex: That sounds like a continuous process rather than a single turn.
Jordan: It is, and we call that the observe-think-act loop. First, the agent observes the current situation—that could be your prompt, a search result, or a tool output. Next, it thinks, deciding what the next useful step should be. Then, it acts by using a tool, producing a response, or requesting info. Then it repeats the loop until the job is done.
Alex: That connects back to Day 42 on tool calling. The model isn't just calling a tool once; it uses tools repeatedly inside a loop.
Jordan: Right. And it also ties into Day 41 on grounding. The agent needs to ground its choices in actual observations and tool results, not in wild guesses.
Alex: You mentioned improvising earlier. How does an agent balance following a plan versus adjusting on the fly?
Jordan: Think about asking for help choosing a used laptop under five hundred dollars for writing and coding. An useful agent starts by clarifying missing requirements, like battery life or screen size. Then it searches listings, compares options against your needs, summarizes tradeoffs, and recommends the best fit. If search results change along the way, it adapts. It blends planning with improvising.
Alex: That makes me think of a road trip navigator in your car. You set the destination, and it maps a route. But if there's sudden traffic or a closed exit, it reroutes you based on real-time feedback.
Jordan: That navigator analogy is spot on. It doesn't just describe the route once and stop. It keeps adjusting as new information arrives. That brings us to feedback and stopping conditions. Feedback is information telling the agent whether a step actually helped. A stopping condition is the rule for when to end the loop, like reaching the goal, running out of progress, or hitting a safety limit.
Alex: Because more steps aren't always better. If it already has solid evidence, looping forever just wastes time.
Jordan: Exactly. Take customer support triage as a real-world example. A customer emails saying, I was charged twice and need this fixed today. An agent classifies the request as billing, retrieves the customer's transaction records, checks if duplicate charges exist, and drafts a response grounded in those exact records. If the issue is complex or ambiguous, it escalates to a human.
Alex: That brings retrieval, grounding, tool use, and stopping conditions together in one workflow. But where do agents break down?
Jordan: They can fail if the goal is unclear, the tools are weak, or retrieved data is incomplete. And there's a serious risk from Day 38: prompt injection. Because agents read outside web pages or emails and take real actions, untrusted text can override their instructions. Good agent design treats all outside inputs as untrusted content until verified.
Alex: The more actions an agent can take, the bigger the threat if untrusted text sneaks in.
