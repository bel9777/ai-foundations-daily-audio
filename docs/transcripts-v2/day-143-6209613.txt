Alex: Did you see AI Weekly covering Ai2's Olmo Hybrid a couple of weeks back? They claim swapping out regular attention layers for Gated DeltaNet beats their standard Olmo 3 7B model.
Jordan: I did. It is actually renewed coverage of an architecture Ai2 detailed earlier this year, but the interest is real because the model is fully open weights. You can actually inspect how they married transformers with linear recurrent neural networks.
Alex: And it is not just Ai2. NVIDIA's Nemotron 3 Ultra report from June is running a hybrid Mamba-Transformer setup, too.
Jordan: Exactly. Everyone spent seven years declaring recurrent models dead. Now frontier teams are bringing them right back into the engine room.
Alex: Understanding why transformers replaced recurrent networks, and why recurrent layers are sneaking back in, is the secret to keeping your inference bills from exploding. This is AI Foundations, lesson 24.
Jordan: Let's start with the classic setup. Before 2017, if you had sequential data like text or sensor logs, you used a Recurrent Neural Network. A vanilla RNN reads an input token, combines it with a running memory vector called the hidden state, and outputs an updated hidden state using the exact same weights at every step.
Alex: Andrej Karpathy had that famous 2015 blog post on the unreasonable effectiveness of RNNs. But how does that hidden state actually hold a whole sentence?
Jordan: Think of the hidden state like a running bank balance. You can process ten transactions or ten million transactions, and the balance is still just a single number. That makes it incredibly fast and cheap to maintain. But if I ask you to audit transaction number forty-eight twelve from just the balance, you cannot do it. Specific details get compressed away. Attention, which transformers use, is the full itemized general ledger. Every single transaction stays retrievable, but the ledger gets heavier and more expensive to search as it grows.
Alex: Right, and training those classic RNNs was brutal. Backpropagation through time, right?
Jordan: Yes. To train an RNN, you unroll it across time. If a sequence has a thousand tokens, it acts like a one-thousand-layer network where every layer shares identical weights. When you backpropagate the error back to the beginning, you multiply by those weight matrices at every single step.
Alex: If the numbers you multiply are slightly below one, the gradient shrinks to zero. If they are above one, the gradient blows up to infinity.
Jordan: That is the vanishing and exploding gradient problem. Exploding gradients give you NaN errors. Vanishing gradients mean the model physically cannot learn connections between tokens separated by more than a brief window.
Alex: Which is why Hochreiter and Schmidhuber gave us the Long Short-Term Memory network in 1997.
Jordan: Precisely. The LSTM introduced an explicit cell state that updates additively. It uses small gating networks with sigmoid activations: a forget gate to decide what to drop, an input gate to decide what to write, and an output gate. Because the cell state update is additive, the gradient can flow backward almost untouched when the forget gate is near one.
Alex: Like the residual connections we talked about in Lesson 22. A gradient highway.
Jordan: Exactly the same intuition. The GRU, or Gated Recurrent Unit, simplified that down to two gates in 2014. But then sequence-to-sequence models ran into the bottleneck problem.
Alex: Sutskever's encoder-decoder architecture.
Jordan: Right. You had one LSTM read an entire French sentence into a single final vector, and a second LSTM tried to generate the English translation purely from that vector. If the sentence was forty words long, the translation fell apart because one vector could not hold all the nuance.
Alex: So Bahdanau added attention in 2014, letting the decoder peek back at every intermediate encoder state. And then the Attention Is All You Need paper in 2017 realized, why bother with the recurrent steps at all?
Jordan: And crucially, GPUs could not train RNNs efficiently because step two strictly depends on step one. Transformers process the entire sequence in parallel during training. Training throughput won the war.
Alex: But now recurrent layers are returning in models like Mamba and Olmo Hybrid. What changed?
Jordan: Modern linear recurrences remove the non-linear activations wrapping the hidden state. Because the state transition is linear, you can use associative parallel scans to train them across time on GPUs just like transformers. At inference, they revert to RNN mode: processing token by token with a fixed-size memory that never grows. The catch is exact recall. If you need to copy a verbatim sixty-character string from five thousand tokens ago, a pure linear RNN still struggles. So teams build hybrids: mostly recurrent layers for speed, with a few attention layers sprinkled in for exact retrieval.
Alex: That bottleneck trade-off reminds me of Google's 2016 Smart Reply system for Gmail. That was an LSTM encoder-decoder, right?
Jordan: It was. One LSTM encoded the incoming email into a thought vector, and a decoder scored suggested quick replies. Long threads failed whenever the critical question was buried in paragraph one because it got squeezed out of the hidden state.
Alex: But the system engineering was clever. They put a cheap classifier upfront to decide if an email even warranted suggestions before spinning up the heavy model, constrained the outputs to a safe, curated list, and forced the three suggested chips to be semantically diverse.
Jordan: Which is the exact architecture you should use today when building automations around large language models. Now, let's see how well you internalized this. Quiz time.
Alex: Hit me.
Jordan: Question one. Your Gmail automation processes four hundred vendor emails in a loop. After each email, Claude rewrites a running three-hundred-word open issues summary for the next step. By the end, a disputed invoice figure from email number twelve is completely wrong. What is the structural failure, and how do you fix it?
Alex: That is an RNN bottleneck where plain text is the hidden state. Every time Claude rewrote the summary, it acted like a lossy forget gate. Over four hundred iterations, email twelve's details vanished. The fix is to stop forcing exact facts through the summary. Extract amounts, dates, and invoice IDs into a structured key-value store or database at each step. That acts like an attention lookup, while the running summary only handles narrative context.
Jordan: Spot on. Question two. You train an LSTM on two years of daily farm sensor data. Some training runs crash with NaN loss. Others run fine but completely ignore weather trends older than two weeks. Diagnose both, and give me a fix for each.
Alex: The NaN loss is exploding gradients from multiplying factors greater than one across the unrolled time steps. Fix that with gradient clipping and maybe lower the learning rate. Ignoring everything past two weeks is vanishing gradients, meaning the forget gates are zeroing out old history. You can fix that by initializing the forget gate bias to a positive number like one or two so it defaults to remembering, or explicitly feed in lag features like last year's same-week reading.
Jordan: Exactly right. Last one. You are choosing between a recurrent hybrid and a pure transformer. Task A is streaming months of machine logs to detect anomalies. Task B is extracting exact lease terms and covenants from two-hundred-page ground leases. Which model gets which job?
Alex: Streaming logs gets the hybrid. The log stream is endless, so a fixed-size state keeps inference cost flat per token, and anomaly detection only needs general pattern memory. The ground leases get the pure transformer. Extracting legal clauses requires verbatim recall from specific pages, which is the classic weak spot of a recurrent hidden state.
