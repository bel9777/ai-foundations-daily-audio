Alex: Trying to make a single AI model handle research, drafting, and fact-checking all at once is like forcing one line cook to take orders, grill steaks, wash dishes, and run the register. This is AI Foundations, day 45.
Jordan: Exactly. Eventually, that poor cook drops a plate. Today we are talking about multi-agent systems and delegation, which is how we fix that exact problem.
Alex: So instead of one massive prompt trying to do everything, we build a team of smaller AI agents that pass work around?
Jordan: Right. A multi-agent system is just two or more agents working together on a single task. Delegation means one agent hands off a specific subtask to another agent because that second agent is specialized for it. Think back to our kitchen: one person takes orders, one cooks, one plates, and someone checks quality.
Alex: That sounds neat, but does adding more agents actually make things better, or does it just add extra noise?
Jordan: It can easily add noise if you are not careful. The main reason to use multiple agents is division of labor. If a task naturally splits into steps—like researching facts, drafting a response, checking for errors, and summarizing—giving each agent a narrow role keeps things focused. But more agents mean more moving parts, which brings risks like agents repeating work or arguing with each other. A good rule of thumb is to never split a task into multiple agents if a single agent can do it reliably. Multi-agent design has to earn its complexity.
Alex: Makes sense. Keep it simple until simple breaks. So if we do split the work, how do agents actually talk to each other?
Jordan: Through handoffs. When one agent delegates to another, it sends a handoff message. And the secret to good handoffs is precision. You do not just tell an agent to look into this. A good delegation message defines three things: the goal, the constraints, and the output format.
Alex: Give me an example of what that looks like in practice.
Jordan: Instead of saying check battery issues, a planner agent tells a researcher agent: Find two risks of using batteries in cold weather, and return bullet points with one sentence each.
Alex: Specific goal, explicit limit, clear format. That way the researcher knows exactly when its job is done. But how do we structure how the whole team interacts?
Jordan: We use coordination patterns. There are three main ones. First is manager-worker, where one manager agent assigns tasks to specialized worker agents. Second is the pipeline, where output flows straight from one agent into the next, like collect facts, then draft, then review. Third is the committee, where several agents generate answers independently, and a final step combines them.
Alex: Manager-worker seems like the easiest starting point for most builds.
Jordan: It definitely is. But regardless of the pattern, team agents need a way to share information, which brings us to shared workspaces.
Alex: Back on day 44, we talked about an agent's private state—the memory it keeps while looping through think, act, and observe. Is a shared workspace just a shared state for the whole group?
Jordan: That is it—a central place where all agents read and write notes, decisions, or intermediate results. Remember our retrieval-augmented generation lessons from days 39 through 41? If a researcher agent retrieves specific source documents, it writes them to the shared workspace. That way, the writer agent uses those exact grounded sources instead of making things up.
Alex: And without that shared workspace, the writer agent might just re-run the search or hallucinate its own facts.
Jordan: Precisely. Without shared memory, you get failure modes like task overlap, role confusion, false confidence where one agent blindly trusts a bad answer from another, or worst of all, infinite looping where agents pass a task back and forth forever.
Alex: Let us walk through a concrete example. Say a customer asks a support system about a complex product question. How does a team handle that?
Jordan: First, the planner agent reads the customer request and splits it into research and drafting steps. The researcher searches the product documentation and discovers that a specific requested feature is actually unavailable, so it writes that key fact to the shared workspace. Next, the writer agent reads the shared workspace and drafts a polite, clear response using that fact. Finally, a critic agent checks the draft against the original product notes in the workspace to make sure the writer did not accidentally promise the missing feature.
Alex: That makes the value of roles clear. The writer focuses on tone, while the critic focuses strictly on accuracy.
Jordan: Exactly. Time for a quick knowledge check to see if this stuck. Question one: What is delegation in a multi-agent system?

Alex: The benefit is division of labor—each agent gets a narrower, cleaner job. The risk is that added complexity can cause role confusion, repeated effort, or infinite loops.

Alex: A shared workspace lets agents store and read common notes, retrieved sources, and intermediate decisions so the team stays on the same page and avoids duplicating work.
