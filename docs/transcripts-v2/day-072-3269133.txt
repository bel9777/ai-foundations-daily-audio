Alex: You can feed two AI models the exact same dataset, but if their internal blueprints are different, they will end up behaving like completely different creatures. This is AI Foundations, day 72.
Jordan: That blueprint is what we call model architecture. It is the structure of how parts connect and how information flows through the system.
Alex: When you say blueprint, are we talking code or math?
Jordan: Think of it like a floor plan for a house. Training the model is like moving in the furniture and decorating. But the architecture is where the walls, doors, and hallways sit. If you have a terrible floor plan, it does not matter how nice your sofa is. The rooms will still feel awkward to walk through. In AI, architecture determines speed, memory footprint, accuracy, and what the model is actually good at doing.
Alex: Let us start with the core building blocks. At the lowest level, what makes up that floor plan?
Jordan: Layers. A neural network is basically a stack of layers that pass numbers back and forth. You have an input layer where raw data enters, like pixel values, audio waves, or tokens from text. Then you have hidden layers in the middle. That is where the model extracts features and intermediate patterns. Finally, you have an output layer that turns those calculations into a prediction, whether that is a category label, a numerical score, or the next generated word.
Alex: And inside those layers are the parameters.
Jordan: Right. Parameters are the adjustable dials inside each layer. Training is just turning those dials until the outputs match your goals. But the architecture determines how many dials exist and how they are wired together.
Alex: Which brings us to the different families of models. They are not all wired the same way.
Jordan: Not at all. The simplest one is a feedforward network. Information travels in one direction, straight from input to output, with no loops. They are straightforward, lightweight, and great for standard tabular data like spreadsheets.
Alex: But terrible for things like photos.
Jordan: Exactly, because photos have spatial patterns. For that, we use convolutional neural networks, or CNNs. A convolution scans tiny patches of an image at a time, looking for local features like edges, textures, and curves. It combines those tiny details into shapes, and shapes into objects.
Alex: And then there are transformers, which seem to run half the tech world right now.
Jordan: Transformers took over because of one main mechanism: attention. Attention allows the model to dynamically weight different pieces of the input so it can focus on what matters most at any given moment.
Alex: Give me an example of attention in action.
Jordan: Take the sentence: The trophy did not fit in the suitcase because it was too big. If I ask you what was too big, you immediately know it was the trophy, not the suitcase. A transformer uses attention to connect the word "it" back to "trophy" across the sentence, instead of treating every word equally or forgetting what came earlier.
Alex: Okay, so once you pick a family, say a transformer, how do you decide how big to build it?
Jordan: You balance three core tradeoffs: depth, width, and sequence length. Depth is the number of layers stacked on top of each other. Deeper networks can learn more complex relationships, but they are harder to train and slower to run. Width is the size of each layer, essentially how many numbers it holds at each step. Wider layers hold more information at once, but they chew through memory and compute fast.
Alex: And sequence length is how much context it takes in at once.
Jordan: Right. For text, longer sequence lengths mean you can feed in an entire research paper instead of just a paragraph. But the compute cost shoots up fast. This ties straight back to Day 69 on robust agent design. The biggest, deepest model is useless if it costs ten dollars per query and takes thirty seconds to reply to an end user.
Alex: Right, raw power means nothing if the system falls over in production. Which leads into modular design. Instead of making one giant monster model do everything, you break the system into specialists.
Jordan: That is the modern approach. You separate the system into smaller, dedicated modules. One module handles fact retrieval, another reasons over the text, and another formats the output. Back on Day 67, we talked about interpretability. If a modular system gives a bad answer, you can check whether the retrieval step failed or the reasoning step failed. With a single opaque model, you are left guessing.
Alex: Let us walk through the customer support assistant example from the lesson. If you run an online shop, how do you architect that?
Jordan: You do not just deploy one transformer and hope it memorized your return policy. You use a transformer as the conversational engine. Next, you plug in a retrieval module that fetches live order data and store policies from an external database. Then you add a safety module that inspects incoming and outgoing messages to block leaks of private customer data.
