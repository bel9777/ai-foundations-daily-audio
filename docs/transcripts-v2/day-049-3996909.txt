Alex: Break those three down for us.
Jordan: Logs record specific events, like user prompts, tool responses, and timestamps. Traces map out the step-by-step path of a single request from input to final answer. Metrics are numbers that show trends over time, like your error rates or response times.
Alex: So when those footprints show that a request went off the rails, that is where failure analysis comes in. But you mentioned earlier that people often stop at the wrong point during an investigation.

Alex: The root cause being the deepest practical reason for the failure.
Jordan: Exactly. The real culprit might be a vague prompt, missing context, poor retrieval, or a tool returning stale data. Any breakdown that impacts the user is an incident, whether it is a total crash, a slow response, or a bad citation.
Alex: So to debug an incident properly, you walk through a set of clear questions. What was supposed to happen, what actually happened, where did they diverge, which layer broke, how do you reproduce it, and what fix prevents it next time.
