Jordan: That blueprint is what we call model architecture. It is the fundamental floor plan that dictates how an AI takes in information, transforms it, and spits out an answer.

Jordan: Exactly. In AI, the materials are the data and training methods. The architecture determines how information moves through the rooms. That comes down to a few core building blocks: layers, connections, attention, and memory structures.

Jordan: Parameters are the learned numbers inside the model that actually make the decisions. Architecture does not replace parameters; it organizes them. It decides where those numbers live and how they get applied.

Alex: So what are the main design ideas behind the models we use today?
Jordan: Three you should know: sequence processing, attention, and modularity.
Alex: Sequence processing is about order, right? "Dog bites man" versus "man bites dog."
Jordan: Exactly. Language and time-based events are ordered. If you scramble the sequence, you destroy the meaning. A sequence-friendly design keeps that order intact.
Alex: And attention is the spotlight.
Jordan: It lets the model decide which parts of the input matter most right now. If a customer sends a five-paragraph message and buries a refund number in paragraph four, attention zeroes in on that number instead of getting distracted by the small talk. Alex: What about modularity? We touched on this back on day 91 with agents and tools.
Jordan: Modularity means splitting up the work. Instead of making one giant model handle language parsing, database search, and calculation, you break the system into specialized components with clear roles. It makes the system easier to test, update, and secure.
Alex: But none of this comes for free. Every design choice has trade-offs.
Jordan: Always. If you want more flexibility to handle any task, you pay for it with higher training and serving costs. If you expand the context window so the model reads longer text, your latency spikes. Latency is just the delay between sending a prompt and getting a response.
Alex: Right, which ties back to day 95 on deployment economics. If you build a real-time support bot that gives brilliant answers but takes twenty seconds to respond because of latency, users will abandon it.
