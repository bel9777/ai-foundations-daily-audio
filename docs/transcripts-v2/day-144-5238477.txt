Jordan: Most people building LLM automations just guess their costs or wait for an unpleasant shock on their credit card bill. But language models do not read characters or words. They read tokens, and providers charge different rates for input tokens versus output tokens. 
Alex: And you do not need any external packages for this lab, right? Just standard Python 3.9 or newer.
Jordan: Completely standard library. No pip install required. You will want an Anthropic API key because Anthropic has a free token counting endpoint, POST slash v1 slash messages slash count tokens. It calculates the exact token count for your specific model without actually running an inference.

Alex: How should we format those files?
Jordan: Put your system prompt first, then a single line with five equals signs, the word USER, and five equals signs, followed by your user payload. Our script looks for that separator. If it is not there, it treats the whole file as user text.
Alex: Got it. Then we drop in token cost dot py right next to the folder. What does the script actually do?
Jordan: You configure three things at the top: your model ID string, your input and output price per million tokens from the provider pricing page, and a small dictionary defining how many times each job runs per month and its typical output token count. Then it loops through your prompt files. It estimates tokens offline by dividing character count by four, and if you have your API key set, it sends the prompt to the count tokens endpoint for the exact count. 
Alex: And it calculates characters per token and monthly cost, then spits out a clean CSV file called token costs dot csv.
Jordan: Exactly. And you should run it offline first. Unset your API key and run the script. You will see every file prints out with an exact count of None, and the characters per token ratio will sit right at four. That is just our fallback heuristic agreeing with itself.
Alex: Then we set the key again and run it for real. What jumps out in the real data?
Jordan: Look closely at that characters per token column. For standard English prose, like podcast notes or conversational instructions, you will usually see three point five to four point five characters per token. But look at your spreadsheet prompt or structured code. Tabular data, comma-separated values, and email headers have tons of punctuation and short numbers, so the ratio drops significantly.
Alex: Meaning fewer characters per token, which makes the prompt much denser in tokens than plain English text. 
Jordan: Spot on. The character heuristic severely undercounts tables and code. Now, when you open the CSV in Excel and sort by cost per month, you notice something else surprising: run frequency almost always trumps prompt length. A short email triage prompt that fires every fifteen minutes runs nearly three thousand times a month. That will dwarf a massive creative prompt you only run once a week. Plus, output tokens are priced several times higher than input tokens.
Alex: That makes total sense. Then the final piece of the lab is adding that fifteen-line usage logger right into our production loops. 
Jordan: Right. Forecasts are great, but providers bill you on reality. The logger reads the usage block from the API response, pulling input tokens, output tokens, and cache stats, then appends a timestamped line to usage log dot csv.
Alex: Now, before we get to the quiz, what are the biggest traps that can mess this up?
Jordan: Three main ones. First, undercounting because you only measured your prompt text file. In a live system, you might have hidden tool schemas, system parameters, or conversational history. In tools like Claude Code, turn twelve resends all the previous turns. Second, using the wrong tokenizer. If you use OpenAI's tiktoken library to count tokens for a Claude model, the numbers will disagree because every model family tokenizes text differently. Third is simple API failures: a mistyped model string giving a four hundred, an expired key in your cron job throwing a four hundred and one, or hitting rate limits.
Alex: Ready for the check questions. Hit me.
Jordan: Question one: Imagine a twelve-turn Claude Code session where the very first turn takes eight thousand input tokens. Why will the session total be vastly higher than twelve times eight thousand?
Alex: Because language models are stateless. Every single turn re-sends the entire conversation up to that point. Turn two sends turn one plus the new reply. Turn twelve sends turns one through eleven, including all tool definitions, file reads, and bash outputs. The input size compounds every single turn, growing roughly quadratically.
Jordan: Perfectly nailed. Question two: For an Excel summary prompt, the characters divided by four rule guessed two thousand tokens, but the counting endpoint returned twenty-nine hundred tokens. Why the gap, and which number belongs in your budget?
Alex: The gap happens because numbers, commas, row breaks, and delimiters do not group into long token chunks like regular English words do. Tabular data is token dense, so the heuristic undercounts it. For your budget, you always use the endpoint number, twenty-nine hundred, because that reflects the actual tokenizer the model uses.
Jordan: Last one. Your Gmail loop runs every fifteen minutes. Each run takes six thousand input tokens and three hundred output tokens. But seventy percent of the time, there are no new emails to process. What is the monthly formula, and what is the cheapest fix?
Alex: Fifteen minutes means four runs an hour, ninety-six a day, or twenty-eight hundred and eighty runs a month. Multiply that out: twenty-eight hundred and eighty times six thousand input tokens is seventeen point two eight million input tokens. Output is twenty-eight hundred and eighty times three hundred, which is zero point eight six four million output tokens. The cost formula is seventeen point two eight times the input price per million, plus zero point eight six four times the output price per million.
Jordan: And the cheapest fix?
Alex: Do not call the model if you do not have to! Use the regular Gmail API in Python to check for unread messages first. If the inbox is empty, exit immediately. That wipes out seventy percent of your bill without touching prompt engineering or model swapping.
