Alex: Thinking Machines Lab put out a model called Inkling 2 Mini on November 20, and MarkTechPost covered it as a 20-gigabyte open-weights model designed to run on a laptop. But the weird part is how it runs. It only has 24 physical layers, but it loops through the middle twelve layers three times.
Jordan: Right. Then three days later, Z.ai launched GLM-5.4 using the exact same looping trick at a massive scale. We should treat both labs' performance benchmarks as unverified for now, especially since GLM-5.4 is locked behind a paid plan. But the computer science behind it isn't brand new. It goes all the way back to the Universal Transformer paper in 2018.
Alex: Instead of stacking fifty or sixty separate layers, you just reuse the middle blocks over and over.
Jordan: Exactly. You recycle the weights. But that trick only makes sense if you understand how a transformer is built in the first place: a conveyor belt of identical blocks that read and write to the exact same stream.
Alex: Understanding that one single block explains why long prompts cost real money, why eight billion parameters tells you about memory but not speed, and how to read releases like Inkling without getting lost. This is AI Foundations, lesson 26.
Jordan: So take one token stepping into the model. What happens first?
Alex: It turns into a vector, which is just a list of numbers. In Llama 3 8B, that vector is 4,096 numbers wide.
Jordan: Right. And that vector steps onto what we call the residual stream. Think of the residual stream as a shared general ledger for a month-end close. The token embedding is the opening balance. As the token flows through the layers, each layer inspects the ledger, does some math, and adds an adjusting entry back onto it. The formula is literally x equals x plus the layer's output. Layers never overwrite the vector; they only add to it. So at the end, the closing balance is the starting embedding plus every adjustment made along the way.
Alex: And each layer has two distinct workers making those adjustments.
Jordan: Attention and the MLP, or multi-layer perceptron. They do completely different jobs. A short way to remember it is that attention communicates, while the MLP computes.
Alex: Unpack that difference.
Jordan: Attention looks across the sequence. Each token sends out queries and keys to ask which other tokens it needs to pay attention to, then pulls in their information. It mixes information across different positions. But the MLP only looks at one position at a time. It takes that token's vector, widens it, runs it through a non-linearity, and squeezes it back down. That is where the model stores most of its factual knowledge. Before each of those steps, a normalization layer like RMSNorm keeps the scale of the numbers stable.
Alex: Wait, if attention mixes positions, how does the model know what order words are in?
Jordan: On its own, it doesn't. Pure attention treats a prompt like a bag of words. We have to inject position. Older models like GPT-2 added learned position vectors at the start. Modern models like Llama use rotary position embeddings, or RoPE, which rotate the query and key vectors based on where the word sits. And because this is a text generator, we slap on a causal mask.
Alex: Which stops tokens from looking ahead into future tokens.
Jordan: Right. Token five can only see tokens one through four. That causal mask is what lets us train the model on entire documents in parallel while still forcing it to predict the next word.
Alex: Once the vector makes it through all those layers of communicating and computing, how does it become an actual word?
Jordan: The output head. It takes that final 4,096-number vector, normalizes it, and multiplies it by an unembedding matrix. That produces a raw score, a logit, for every single word in the vocabulary, which is 128,000 words in Llama 3. Softmax turns those scores into probabilities, the model samples a token, appends it to the prompt, and runs the entire loop again.
Alex: Let's do the math on Llama 3 8B, because looking at where the eight billion parameters actually live blew my mind.
Jordan: Meta's paper shows 32 layers, hidden width 4,096, and an MLP inner dimension of 14,336. In each layer, attention takes about 42 million parameters. Meta used grouped query attention, so 32 query heads share eight key-value heads to save memory. But the MLP in that same layer takes 176 million parameters across its three projection matrices.
Alex: The MLP is four times larger than attention!
Jordan: Roughly 80% of each block's parameters sit inside the MLP, not attention. Across all 32 layers, the MLPs eat up about 5.6 billion parameters, while attention takes about 1.3 billion. Add the 128,000-token embedding table and output head, which take another billion, and you land right at 8.0 billion parameters.
Alex: And none of those parameter numbers change whether my prompt is ten words or ten thousand words.
Jordan: Not by a single byte. The weights stay static. What grows with sequence length is the computation inside attention and the memory needed to store past tokens.

Jordan: Spot on. The instruction only gets combined with the email at the very final positions. Moving instructions to the top lets every single email token be processed in light of the instructions.
