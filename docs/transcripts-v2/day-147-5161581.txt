Alex: Understanding attention explains why long documents cost real money and where your prompt details get lost. This is AI Foundations, lesson 25.
Jordan: In lesson 24, we saw recurrent networks try to compress an entire sequence into a single hidden state step by step, which meant the beginning of a long text faded out. Attention removes that bottleneck. Every token can look directly at every other token.
Alex: And each token gets three vectors: query, key, and value. You call this a soft VLOOKUP. Walk me through that.
Jordan: In a spreadsheet, VLOOKUP takes a search term, finds an exact matching row in a key column, and returns the value from that row. Attention does that smoothly. The query is what a token is looking for. The key is what each candidate token offers, like a label. The value is the content it hands over if chosen. Attention compares the query to every key, turns those match scores into weights that add up to one, and returns a weighted average of all the values. Weak matches still contribute a tiny bit, and the whole thing is differentiable, so backprop can train it.
Alex: The formula from Vaswani in 2017 is scaled dot-product attention: softmax of Q times K transpose over the square root of the key dimension, all multiplied by V.
Jordan: The dot product measures how well the query matches each key. Softmax turns those scores into percentages. And dividing by the square root of the key dimension keeps the variance stable so gradients do not vanish.
Alex: Let's run the numbers from the lesson. Suppose the word "it" has a query of one, one, with key dimension two.
Jordan: And we have three earlier tokens: "loan", "barn", and "covers". Their keys give raw dot products of three, two, and one. We divide by the square root of two, which is about one point four one four. That scales our scores down to two point one two, one point four one, and zero point seven one.
Alex: Then we exponentiate and divide by the sum, which is fourteen point four eight.
Jordan: Giving weights of roughly point five seven six for "loan", point two eight four for "barn", and point one four zero for "covers". Multiply those weights by their value vectors and add them up, and the new vector for "it" is mostly "loan", partly "barn", and a little "covers". A trained model learns keys and queries that push the weight onto the right referent.
Alex: And in a chatbot, words cannot peek into the future.
Jordan: That is the causal mask. We set all future position scores to negative infinity before the softmax, forcing their weights to zero so the model can generate text one token at a time.
Alex: Plus, one attention pass cannot track grammar, pronoun references, and numbers simultaneously, so models run multiple heads in parallel.
Jordan: Multi-head attention, exactly. But scoring every token against every other token means n-squared compute. Doubling your context quadruples those score calculations. And during generation, the model must store the keys and values of every previous token in the KV cache so it does not recompute them.
Alex: Which eats VRAM alive. Meta's Llama 3 8B uses grouped-query attention, where eight key-value heads support thirty-two query heads. Even with that, it needs about one hundred twenty-eight kilobytes of cache per token. An eight-thousand-token prompt requires one gigabyte of memory just for one user.
Jordan: And without grouped-query attention, it would be four gigabytes. That is why vendors charge premiums for long prompts. Ready for a quiz?

Jordan: Your contractor builds a custom attention layer with key dimension two hundred fifty-six and drops the square root scaling factor to keep the code simple. Training loss barely moves. What happened, and what is the fix?
Alex: When your query and key dimensions are two hundred fifty-six, the variance of their dot product jumps to two hundred fifty-six, which is a standard deviation of sixteen. That spreads the raw scores way too far apart. Softmax turns into an extreme winner-take-all spike where one score gets a weight of one and the rest get zero. When softmax saturates like that, its gradients drop to almost zero, so backpropagation stalls out completely. The fix is dividing the scores by the square root of two fifty-six, which is sixteen, and checking weight initialization.
Jordan: Spot on. Second scenario: you self-host a Llama 3 8B model. You bump your context from eight thousand to sixteen thousand tokens across four concurrent conversations. What happens to the KV cache footprint and prefill compute?
Alex: The KV cache scales linearly with length. At one hundred twenty-eight kilobytes per token, sixteen thousand tokens is two gigabytes per conversation. Multiply by four chats, and that is eight gigabytes of cache alone, on top of roughly sixteen gigabytes for the model weights. Meanwhile, attention-score compute during prefill scales quadratically, so doubling the context quadruples the score calculations for every conversation.

Alex: Tell them absolutely not. Attention weights form a softmax distribution, not a calibrated explanation of what the model actually relied on.
