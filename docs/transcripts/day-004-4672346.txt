The Mental Model

Generalization means using what was learned from past examples to make good decisions on new examples. Memorization is different. A model can store details of training data and appear impressive when tested on those same cases. But the real job is usually outside that set: new customers, new weather, new transactions, or the next batch of records. Think of a student preparing for an exam. A student who memorizes answers to a practice sheet succeeds if the teacher repeats it. A student who understands the underlying ideas can answer a new question with different wording. Generalization is that second kind of learning. To check it, separate examples into sets. The training set is where the model adjusts settings and learns patterns. A validation set is used while improving the model to compare choices without treating practice answers as proof. A test set is held back until the end for an honest final check. Each set represents data the model did not directly learn from at that moment. Overfitting happens when a model becomes too tuned to quirks in training data. It may capture noise, coincidences, or details that will not repeat. Training performance can look excellent while validation or test performance is worse. Underfitting is the other problem: the model is too simple or insufficiently trained to capture a useful pattern even in training examples. Evaluation must match the goal. Accuracy can be useful when classes are balanced and mistakes cost about the same. In other situations you may care more about missed cases, false alarms, average error, or another measure. A Real-World Example

Suppose you want a model to estimate how many farm delivery orders will arrive on a route. You have past records with dates, neighborhoods, order counts, and perhaps weather. If you train and judge the model on the same old records, it may learn peculiarities of those weeks rather than the demand pattern you need. Reserve later records for validation and testing. Train on earlier weeks. Use validation to compare changes, such as adding an input or choosing a simpler model. Then test once on records the model has not seen. If performance holds up, you have evidence that it may generalize. Choose a measurement that matters. A small average error might be acceptable for staff planning, while regularly underestimating a busy route could be costly. The test is not a ceremony. Recap and One Action

Three takeaways. First, generalization is performance on new examples, not just old ones. Second, training, validation, and test sets create an honest way to check it. Third, overfitting can make training performance look better than real-world performance. One action: choose one forecast or judgment you make regularly and write down one past example you would learn from and one future-like example you would hold back.
