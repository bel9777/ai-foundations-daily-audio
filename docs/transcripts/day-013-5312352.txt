AI Foundations — Day 13: Confusion Matrices and Classification Tradeoffs

Day 13: Confusion Matrices and Classification Tradeoffs Objective: Learn how a model’s classification mistakes break down in a confusion matrix , how to interpret the different kinds of errors, and how to choose a decision threshold that fits the real-world goal. Prerequisites: You should be comfortable with classification, decision boundaries, loss functions, and evaluation metrics like accuracy, precision, recall, and F1 from the recent lessons. Why this matters A classification model does not just make “right” or “wrong” predictions. It makes specific kinds of mistakes. Those mistakes can have very different costs. For example, in spam detection, marking a real email as spam is annoying; in medical screening, missing a sick patient can be serious. A confusion matrix helps you see those differences clearly. 1) Confusion matrix: the error map A confusion matrix is a table that compares the model’s predicted class with the true class. For a simple yes/no problem, it has four outcomes: True Positive (TP) : the model predicts “yes,” and the answer really is “yes.” True Negative (TN) : the model predicts “no,” and the answer really is “no.” False Positive (FP) : the model predicts “yes,” but the answer is actually “no.” False Negative (FN) : the model predicts “no,” but the answer is actually “yes.” These names can feel abstract, so remember the idea: the first word tells you whether the model was right or wrong, and the second word tells you which class it predicted. 2) Precision and recall: two different ways to care about errors From the confusion matrix, you can calculate many metrics. Two of the most useful are: Precision : of everything the model predicted as positive, how many were actually positive? Recall : of everything that was actually positive, how many did the model find? They answer different questions. Precision cares about being careful with positive predictions. Recall cares about not missing positive cases. This is a good place to revisit evaluation metrics that match the goal from Day 12: the best metric depends on what kind of mistake matters most. Accuracy can look fine even when the model is failing in one important direction. 3) Decision threshold: where you draw the line Many classifiers do not just output a label. They output a score or probability, such as “there is a 72% chance this is spam.” A decision threshold is the cutoff used to turn that score into a class label. For example, if the threshold is 0.5, then scores above 0.5 become “positive,” and scores below 0.5 become “negative.” Changing the threshold changes the confusion matrix: Lowering the threshold usually increases positives predicted, which may raise recall but lower precision. Raising the threshold usually makes the model more cautious, which may raise precision but lower recall. This is one of the main classification tradeoffs : improving one measure often worsens another. A tradeoff means you cannot optimize both sides equally at the same time. 4) A memorable analogy: a smoke detector Think of a smoke detector in a kitchen. If it is too sensitive, it will go off when you toast bread. That is like a false positive . If it is not sensitive enough, it might stay quiet during a real fire. That is like a false negative . The “best” detector depends on the setting. In a busy kitchen, a few false alarms may be acceptable. In a warehouse full of flammable material, missing a real fire is far worse. The same logic applies to classification thresholds. 5) Concrete example: spam filtering Imagine a spam classifier for your inbox: False positive : a real message from your boss gets sent to spam. False negative : a spam message lands in your inbox. If the model is too aggressive, it may catch more spam but accidentally hide important mail. If it is too cautious, more spam gets through. The right threshold depends on your priorities. Some people prefer to miss a bit of spam rather than risk losing a real message. Others may prefer strong filtering and check the spam folder carefully. Notice how this connects to Day 7’s decision boundaries . A decision boundary is the line or surface that separates classes. The threshold helps decide exactly where that boundary behaves as “positive” or “negative” in practice. Hands-on exercise: build a confusion matrix by hand You do not need any paid tools. Use a sheet of paper, a notes app, or a spreadsheet. Write down 12 imaginary examples in a binary classification problem, such as “spam” vs. “not spam.” For each example, record the true label and the model’s prediction. Count the number of TP, TN, FP, and FN. Compute precision and recall using those counts. Now pretend you changed the threshold so the model predicts “positive” more often. Estimate how FP, FN, precision, and recall would change. If you want a ready-made scenario, use this mini dataset: True positives predicted correctly: 3 True negatives predicted correctly: 5 False positives: 2 False negatives: 2 From that, calculate precision and recall. Then ask yourself: if false negatives mattered more, would you raise or lower the threshold? Three things to remember A confusion matrix shows which kinds of mistakes a classifier makes. Precision and recall answer different questions, so neither one is always enough by itself. Changing the decision threshold changes the balance between false positives and false negatives.
