AI Foundations — Day 27: Tokens and Context Windows

Day 27 — Tokens and Context Windows Objective: By the end of today, you will understand what a token is, what a context window is, why both matter for transformers, and how they shape what an AI model can and cannot do in one response. Prerequisites: You should be comfortable with the ideas from Days 24–26: sequence models, attention, and the transformer architecture. It also helps to remember that training uses error signals and backpropagation from Days 21–22, because today we’ll connect those ideas to the limits of input length. 1) Tokens: the pieces a model actually reads Humans read text as words and sentences. Models usually do not. They read tokens , which are the chunks of text a model processes as units. A token can be: a whole word, like cat part of a word, like un + believ + able punctuation, like . or ? sometimes a space plus a word fragment, depending on the tokenizer The tokenizer is the rule-based system that splits text into tokens before the model sees it. The model then turns each token into a number pattern it can work with. Why not use words directly? Because splitting into tokens lets the model handle rare words, new words, names, and many languages more flexibly. It also keeps the vocabulary manageable. 2) Context window: the model’s short-term memory The context window is the maximum amount of text a model can consider at one time when producing an answer. Think of it as the model’s working memory for a single conversation turn or document. If the model’s context window is 8,000 tokens, then everything it uses to answer must fit inside those 8,000 tokens: your prompt, the conversation history, and the model’s own previous output in that exchange. This does not mean the model remembers everything forever. It means it can only “look at” a limited amount of text at once. If earlier parts of the conversation fall out of the window, the model cannot directly use them anymore. 3) Why token count matters more than word count One sentence can use very different numbers of tokens depending on the words, punctuation, and language. For example, a short technical term may split into several tokens, while a common word may be one token. So when people say a model has a context window of so many tokens, they are talking about an approximate size limit for text, not a neat number of sentences or paragraphs. Concrete example: Imagine you paste a long support email thread into a chatbot and ask, “What is the customer actually asking for?” If the thread is too long, the earliest messages may fall out of the context window. Then the model may miss the original complaint and focus only on the most recent messages. The result can be an answer that sounds reasonable but is incomplete. 4) The suitcase analogy Here is a memorable way to think about it: Tokens are like items packed into a suitcase, and the context window is the suitcase size. You can pack only as much as the suitcase allows. Bigger items take up more space, and if you add new items, older items may need to be left out. A large suitcase lets you carry more, but it is still not infinite. This analogy is useful because it explains both the benefit and the limitation: Benefit: the model can consider many pieces of text at once. Limitation: once the suitcase is full, some information must be dropped or summarized. 5) How this connects to transformers In a transformer, attention lets each token look at other tokens in the same context window and decide what matters. That is why context length matters so much: attention can only compare tokens that are present in the window. Here is the key link to review from Day 25: attention is the mechanism for choosing what matters. But it can only choose from what is available. If relevant information is outside the context window, attention cannot recover it. And from Day 26: the transformer processes the whole visible sequence in parallel. That makes it powerful, but also bounded by the amount of text it can hold at once. 6) Two practical consequences First: when you write prompts, the exact wording and ordering matter. Important instructions should be placed clearly and near the relevant content so they are less likely to be lost in a long prompt. Second: long documents may need splitting, summarizing, or retrieval methods if they exceed the context window. A model cannot attend to text it never receives. This is one reason AI systems often combine a language model with tools that search documents or fetch relevant passages. The model still has a context window, but external tools help choose what text enters it. Free hands-on exercise Do this with any free notebook, text editor, or even a plain notes app: Write a 250–400 word passage about a topic you know well, such as a hobby, a trip, or a product you use. Underline every place where you think punctuation, numbers, or unusual words might increase token count. Now rewrite the passage in two versions: one concise version and one more verbose version. Compare the two and ask: which version would likely use more tokens, and which parts might a model be more likely to miss if the text were much longer? If you want a second step, paste the passage into any free chatbot and ask it to summarize the first version, then the second. Notice how changes in wording and length can affect the response. That training does not remove the need for finite context at inference time: a well-trained model is still limited by how much text it can see at once.
