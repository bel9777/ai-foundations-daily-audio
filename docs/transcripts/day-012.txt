AI Foundations — Day 12: Evaluation Metrics That Match the Goal

Day 12 — Evaluation Metrics That Match the Goal Objective: Learn how to judge a model using metrics that actually reflect what you care about in the real world, so you can compare models fairly and avoid being fooled by a single number. Prerequisites: You should already be comfortable with labeled examples, classification vs. regression, features, loss functions, and the basic idea of gradient descent from the last few days. Yesterday, we talked about optimization : how a model changes its internal settings to reduce a loss function , which is a number that says how wrong the model is during training. Today we step back and ask a different question: How do we decide whether the trained model is actually useful? 1) Loss is not the same as performance The first important idea is that the metric used to train a model and the metric used to evaluate it do not have to be the same. Evaluation metric means the number you use to judge how well the model performs on data it did not train on. It is your scoreboard. A scoreboard analogy helps here: in a game, the practice drills are not the same as the final score. Training loss is like practice feedback. Evaluation metrics are like the score that tells you whether the model won in a meaningful way. This matters because a model can improve its loss while still making the kind of mistakes you care about most. For example, if a medical screening model almost never misses a disease case, but it incorrectly alarms too often, its training loss might look fine while the real-world outcome is not. 2) Accuracy: useful, but only when classes are balanced The simplest evaluation metric for classification is accuracy . Accuracy means the fraction of predictions that are correct. If a model makes 90 correct predictions out of 100, its accuracy is 90%. Accuracy is easy to understand, but it can be misleading when one class is much more common than the other. This is called a class imbalance , meaning one label appears far more often than the others. Real-world example: imagine a spam filter where only 1% of emails are spam. A model that labels every email as “not spam” is 99% accurate, but it is useless. It never catches spam. So high accuracy does not always mean a good model. 3) Precision and recall: measuring different kinds of mistakes When the cost of false alarms and missed detections are different, we need metrics that separate them. A false positive is a case where the model predicts something is present when it is not. A false negative is a case where the model misses something that is actually present. Two common metrics help here: Precision : of the items the model predicted as positive, how many were truly positive? Recall : of the truly positive items, how many did the model find? In plain language, precision rewards being careful. Recall rewards being thorough. Memorable analogy: imagine a fishing net. Precision is how many fish are in the net compared with trash you accidentally caught. Recall is how many of the fish in the lake you managed to catch. You can make the net tiny and catch only fish, which gives high precision but low recall. Or you can make it huge and catch almost everything, which gives high recall but may also catch more trash. That tradeoff is why evaluation must match the goal. If you are screening for a dangerous disease, missing a sick person may be worse than flagging a healthy person. In that case, recall may matter more. If you are sending expensive alerts to a human team, precision may matter more because false alarms waste time. 4) Regression metrics: measuring distance from the right answer For regression, where the model predicts a number, common evaluation metrics include MAE and MSE . MAE means mean absolute error . It is the average size of the model’s mistakes, ignoring whether they are above or below the true value. MSE means mean squared error . It is the average of the squared mistakes, which makes large errors count much more heavily. If you are predicting house prices, MAE tells you the typical dollar miss. MSE punishes very large misses more strongly, so it is useful when big errors are especially bad. Review from Day 10: the loss function is what the model tries to reduce during training. The evaluation metric is what you use afterward to decide whether that trained model meets your real goal. A model can optimize one thing while you care about another. 5) Train, validation, and test: three different uses of data To evaluate honestly, we usually split data into three parts: Training set : data used to fit the model. Validation set : data used to choose between models or tune settings. Test set : data used once at the end to estimate final performance. The validation set is like a rehearsal audience. You can check whether a model is improving without peeking at the final exam. The test set is the final exam itself. This connects back to Day 11’s gradient descent: the model may keep getting better on training loss while getting worse on validation performance. That is a warning sign that it is learning patterns that do not generalize. Generalize means to perform well on new, unseen data. Free hands-on exercise Use any spreadsheet app or even paper. Create a tiny classification example with 20 items. Label each item as positive or negative. Then make up two models: Model A predicts every item as negative. Model B predicts positive for 6 items, including 4 correct positives and 2 incorrect positives. Now calculate: Accuracy for each model Precision for Model B Recall for Model B Then answer this: which model would you prefer if false alarms are cheap? Which would you prefer if missing a positive case is very costly? This simple exercise shows why a single metric rarely tells the whole story. Three questions to check your understanding Why can accuracy be misleading when one class is much more common than the other? What is the difference between precision and recall in plain language? Why do we use a validation set instead of only looking at training performance? ------------------------------ Answers Accuracy can be misleading because a model can get a high score by predicting the common class almost all the time, even if it fails on the rare but important class. Precision asks, “When the model said positive, how often was it right?” Recall asks, “Of all the true positives, how many did the model find?” We use a validation set to check how the model performs on unseen data while tuning it, so we do not accidentally choose a model that only looks good on the training set.
