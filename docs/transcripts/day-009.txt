AI Foundations — Day 9: Features: Turning Reality into Inputs

Day 9 — Features: Turning Reality into Inputs Objective: By the end of today, you’ll understand what features are, how raw reality gets turned into machine-learning inputs, and how good feature choices can make a model much more useful. Prerequisites: You should be comfortable with the ideas from Days 3–8: the basic machine learning workflow, generalization, data as the model’s experience, labeled examples, classification vs. regression, and learning without labels. Why features matter A model cannot learn directly from “the world.” It learns from numbers. A feature is one piece of input information used by a model to make a prediction. Features are the way we turn reality into something a machine can process. For example, if you want to predict house prices, features might include: Square footage — the size of the home Number of bedrooms Age of the house Distance to downtown These are not the answer. They are the clues. Concept 1: Raw data vs. features Raw data is information in its original form, before we organize or simplify it for a model. A photo, a spreadsheet row, a sensor reading, or a paragraph of text can all be raw data. A feature set is the collection of features we choose to feed into a model. The same raw data can lead to different feature sets depending on the problem. For example, a photo of a dog contains raw data in the form of pixels. A model might use pixel values directly, or it might use features such as “how many edges are present,” “dominant colors,” or “shape patterns.” Important idea: the best features depend on the task. Good features make the signal easier to learn; bad features hide it. Concept 2: Feature engineering Feature engineering means creating or improving features from raw data so a model can learn better. This can include simple actions like: Combining values Turning dates into “day of week” or “month” Measuring counts, lengths, or averages Encoding categories as numbers Why do this? Because the raw form of data is often not the most useful form for learning. A model may struggle to notice patterns that humans can express directly. Analogy: Think of features like ingredients in a recipe. Raw groceries are useful, but not enough by themselves. You chop, measure, and combine them so the final dish becomes recognizable. In the same way, feature engineering prepares data so the model can “taste” the important parts. Concept 3: Encoding categories and making numbers Many real-world inputs are not naturally numeric. A category is a label-like value such as color, city, or product type. Most models still need numbers, so we convert categories into numeric form using encoding . Encoding means translating a non-numeric value into numbers in a consistent way. A simple example is turning a category like: Red Green Blue into numbers such as: Red = 1 Green = 2 Blue = 3 That said, numbering categories can accidentally imply order where none exists. For example, 3 is not “more blue” than 1 is “more red.” So the encoding method matters. The main lesson: features must be represented in a way that matches their meaning. Concept 4: Scaling and normalization Some features have very different ranges. One feature might be age in years from 0 to 100, while another might be income from 0 to 200,000. If values are on very different scales, some models can behave poorly. Scaling means changing feature values so they are more comparable in size. Normalization is one common kind of scaling that adjusts values into a standard range, often between 0 and 1. This does not change the meaning of the feature; it changes the unit so the model can use it more easily. Spaced review from earlier lessons Let’s connect this to Day 5: data is the model’s experience . Features are how that experience gets organized into usable pieces. Good experience is not just “more data”; it is data shaped in a way the model can learn from. And from Day 7: classification and regression are different learning tasks. The features you choose should match the task. For classification, features help the model separate groups. For regression, features help the model predict a number. Real-world example: predicting whether a delivery will be late Suppose you work for a delivery company and want to predict whether a package will arrive late. A raw record might include: Pickup time Destination city Weather Driver ID Distance traveled Useful features might be: Hour of day extracted from pickup time Rush hour flag — whether the pickup happened during a busy traffic period Distance in miles Weather category encoded as numbers Average historical delay for that route Notice what happened: we turned messy real-life information into structured inputs. That does not guarantee a perfect model, but it gives the model a better chance to find a pattern. Free hands-on exercise You can do this with paper, a notes app, or a free spreadsheet. Pick a simple prediction task from daily life. Examples: “Will I bring an umbrella today?” “Will a movie be worth watching?” “Will I finish my work before dinner?” Write down 5 possible raw data sources for that task. Turn each raw source into a feature. For example: “Weather forecast” becomes “chance of rain” “Movie title” becomes “genre” “Workload” becomes “number of tasks remaining” Mark each feature as numeric, categorical, or text. Choose one feature you might scale or normalize, and explain why. Goal: practice seeing the difference between reality and the representation of reality that a model can use. Three things to remember Features are the input pieces a model uses to make predictions. Feature engineering is the process of creating better inputs from raw data. Encoding and scaling help represent real-world information in forms models can use. Knowledge check What is a feature in machine learning?
